02 — Come funziona la Matrice di Eisenhower in ATHENA

La Matrice di Eisenhower — originariamente un framework di produttività personale — è stata adattata per la prioritizzazione degli eventi di Disaster Recovery nell'AI Digital Twin DR Platform. L'idea centrale è semplice: ogni evento di failure nel grafo Neo4j viene classificato lungo due dimensioni ortogonali (urgenza e importanza) per determinare la risposta automatica ottimale, dal playbook immediato alla pulizia differita.

La classificazione avviene automaticamente e in tempo reale al termine di ogni simulazione (POST /api/dr/simulate): il classificatore riceve il risultato del BFS, calcola le due dimensioni e restituisce un quadrante Q1–Q4 incluso direttamente nella response JSON.

⚡ URGENTE ◌ NON URGENTE
IMPORTANTE
NON IMP.
Q1
Urgente · Importante
ESEGUI ORA
→ MCP get_recovery_plan immediato
  • Blast radius attivo — cascading failure in propagazione su Neo4j
  • worst_case_rto_minutes supera il target del nodo origine
  • Lag di replica (replication_lag_min) oltre la soglia RPO
  • Cascade in corso su almeno un nodo a distanza ≤ 2 hops
  • Sistema di produzione (affects_production=True) coinvolto
🔴BFS cascade → get_recovery_plan → PagerDuty escalation
Q2
Non Urgente · Importante
PIANIFICA E MIGLIORA
→ simulate_disaster dry-run + arch recommendations
  • RTO/RPO al 70% del threshold (warning, non ancora breach)
  • Produzione impattata ma entro i tempi di recovery contrattuale
  • Blast radius con nodi critici ma cascading non ancora attivo
  • Simulazione periodica pianificata (dry-run, non-prod)
  • Analisi trend RTO/RPO via VictoriaMetrics (90 giorni)
🟡Scheduler → simulate_disaster → SimulationReport → ARB queue
Q3
Urgente · Non Importante

  • Nessun nodo produzione coinvolto (affects_production=False)
  • RTO entro il target, nessun blast radius critico (distanza > 2 hops)
  • Replica lag entro RPO ma performance degradate
  • Escalation automatica a Q1 se condizione persiste oltre 15 minuti
🔵Static playbook → ServiceNow P3/P4 → escalation timer
Q4
Non Urgente · Non Importante
ELIMINA O ARCHIVIA
→ LRU eviction, Neo4j cleanup, log retention
  • Nessun breach, nessuna urgenza, nessun impatto produzione
  • SimulationCache LRU eviction per simulazioni scadute (> 30 giorni)
  • Alert duplicati da monitoring legacy non integrato nel grafo
  • Nodi orfani nel grafo rilevati da MCP check_drift
  • Log di simulazione oltre il retention period configurato
⚫check_drift → Neo4j cleanup → SimulationCache purge
03 — Algoritmo di classificazione — eisenhower_classifier.py
backend/algorithms/eisenhower_classifier.py — NUOVO · implementato 18/05/2026 
"""
Eisenhower DR Classifier — classifica ogni simulazione in Q1..Q4
Integra: bfs_with_latency · calculate_effective_rto · EnhancedSimulationWithTimeline
"""
from dataclasses import dataclass
from enum        import Enum

class EisenhowerQuadrant(str, Enum):
    Q1 = "Q1"  # Urgente + Importante  → get_recovery_plan immediato
    Q2 = "Q2"  # Non Urgente + Imp.    → simulate_disaster pianificato
    Q3 = "Q3"  # Urgente + Non Imp.    → static playbook + timer
    Q4 = "Q4"  # Non Urgente + Non Imp → cleanup / check_drift

# Costanti
URGENCY_RATIO_WARN:    float = 0.70  # 70% threshold → warning Q3
ESCALATION_WINDOW_MIN: float = 15.0  # minuti prima della promozione Q3→Q1

@dataclass
class EisenhowerInput:
    simulation:          EnhancedSimulationWithTimeline  # da /api/dr/simulate
    rto_target_minutes:  float   # proprietà Neo4j del nodo origine
    rpo_target_minutes:  float
    cascade_in_progress: bool = False
    replication_lag_min: float = 0.0
    affects_production:  bool = True


def classify_dr_event(inp: EisenhowerInput) → EisenhowerQuadrant:
    # Breach: RTO/RPO effettivo supera il target del nodo
    rto_breach = inp.simulation.worst_case_rto_minutes > inp.rto_target_minutes
    rpo_breach = inp.replication_lag_min              > inp.rpo_target_minutes

    # Blast radius critico: ≥1 nodo entro 2 hops dall'origine
    critical_blast = any(n.distance <= 2 for n in inp.simulation.blast_radius)

    # Urgenza: breach o cascading failure già in corso
    is_urgent    = rto_breach or rpo_breach or inp.cascade_in_progress
    # Importanza: produzione coinvolta, nodi critici vicini, o breach confermato
    is_important = inp.affects_production or critical_blast or rto_breach

    if is_urgent     and is_important:     return EisenhowerQuadrant.Q1
    if not is_urgent and is_important:     return EisenhowerQuadrant.Q2
    if is_urgent     and not is_important: return EisenhowerQuadrant.Q3
    return EisenhowerQuadrant.Q4


def apply_escalation(quadrant: EisenhowerQuadrant, elapsed_minutes: float) → EisenhowerQuadrant:
    # Q3 → Q1 se la condizione non è risolta entro ESCALATION_WINDOW_MIN
    if quadrant == EisenhowerQuadrant.Q3 and elapsed_minutes >= ESCALATION_WINDOW_MIN:
        return EisenhowerQuadrant.Q1
    return quadrant
04 — Soglie e parametri di classificazione
Parametro Valore Significato Dove viene letto
rto_target_minutes Da proprietà Neo4j del nodo origine Soglia RTO contrattuale per il nodo. Se worst_case_rto_minutes la supera → rto_breach = True → urgenza e importanza. affected_nodes[origin_node_id]["rto_minutes"]
rpo_target_minutes Da proprietà Neo4j del nodo origine Soglia RPO. Se il lag di replica supera questo valore → rpo_breach = True. Default 15 min se non configurato. affected_nodes[origin_node_id]["rpo_minutes"]
URGENCY_RATIO_WARN 0.70 Al 70% del target si entra in Q3 (warning). Sotto questa soglia e senza urgenze → Q2 o Q4. eisenhower_classifier.py (costante)
ESCALATION_WINDOW_MIN 15.0 minuti Un evento Q3 non risolto viene automaticamente promosso a Q1 dopo 15 minuti tramite apply_escalation(). eisenhower_classifier.py (costante)
cascade_in_progress len(affected_nodes) > 1 Se la simulazione ha più di un nodo nel blast radius, la cascata è considerata in corso. Genera urgenza. api/dr.py post bfs_with_latency()
critical_blast any(n.distance ≤ 2) Se almeno un nodo nel blast radius è a ≤ 2 hops dall'origine, il blast radius è considerato critico. Genera importanza. eisenhower_classifier.py interno
affects_production True (default) Tutti i nodi del grafo ATHENA sono considerati produzione per default. Può essere esteso con una proprietà Neo4j. api/dr.py (hardcoded, estendibile)
