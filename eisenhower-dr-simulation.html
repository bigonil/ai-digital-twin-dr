03 — Algoritmo di classificazione Eisenhower — Python · da aggiungere al progetto
backend/algorithms/eisenhower_classifier.py · NEW — integra con i moduli esistenti 
"""
Eisenhower DR Classifier — integra con i moduli esistenti del progetto:
  cascading_failure.py  → bfs_with_latency()        (già implementato ✓)
  rto_rpo_calculator.py → calculate_effective_rto()  (già implementato ✓)
  playbook_generator.py → generate_playbook()        (già implementato ✓)
  mcp_server/app.py     → simulate_disaster, get_recovery_plan, check_drift (✓)
"""
from dataclasses import dataclass
from enum        import Enum
from models.enhanced_graph import EnhancedSimulationWithTimeline


class EisenhowerQuadrant(str, Enum):
    Q1 = "Q1"  # Urgente + Importante  → get_recovery_plan immediato
    Q2 = "Q2"  # Non Urgente + Imp.    → simulate_disaster pianificato
    Q3 = "Q3"  # Urgente + Non Imp.    → static playbook steps
    Q4 = "Q4"  # Non Urgente + Non Imp → cleanup / check_drift


@dataclass
class EisenhowerInput:
    simulation:          EnhancedSimulationWithTimeline
    rto_target_minutes:  float  # da proprietà Neo4j del nodo
    rpo_target_minutes:  float
    affects_production:  bool
    cascade_in_progress: bool
    replication_lag_min: float = 0.0


def classify_dr_event(inp: EisenhowerInput) -> EisenhowerQuadrant:
    # Valori calcolati da rto_rpo_calculator.py (già implementato)
    rto_breach = inp.simulation.worst_case_rto_minutes > inp.rto_target_minutes
    rpo_breach = inp.replication_lag_min              > inp.rpo_target_minutes

    # Blast radius critico: ≥1 nodo a distanza ≤2 hops (da bfs_with_latency)
    critical_blast = any(n.distance <= 2 for n in inp.simulation.blast_radius)

    # Urgente: breach confermato o cascading failure in corso
    is_urgent    = rto_breach or rpo_breach or inp.cascade_in_progress
    # Importante: impatta produzione o blast radius critico
    is_important = inp.affects_production or critical_blast or rto_breach

    if is_urgent     and is_important:  return EisenhowerQuadrant.Q1
    if not is_urgent and is_important:  return EisenhowerQuadrant.Q2
    if is_urgent     and not is_important: return EisenhowerQuadrant.Q3
    return EisenhowerQuadrant.Q4


# Routing MCP tool per quadrante (mcp_server/app.py)
QUADRANT_MCP_ROUTES: dict[EisenhowerQuadrant, str] = {
    EisenhowerQuadrant.Q1: "get_recovery_plan",  # immediato, priorità max
    EisenhowerQuadrant.Q2: "simulate_disaster",  # dry-run pianificato
    EisenhowerQuadrant.Q3: "get_recovery_plan",  # static steps, auto-exec
    EisenhowerQuadrant.Q4: "check_drift",       # cleanup e orphan detection
}

# Soglie per classificazione warning (Q3) e escalation Q3→Q1
URGENCY_RATIO_WARN:       float = 0.70  # 70% del target → Q3
ESCALATION_WINDOW_MIN:    float = 15.0  # minuti prima della promozione Q3→Q1
04 — Mapping su AI Digital Twin DR Platform — componenti esistenti e nuovi
Neo4j 5.18 · Graph Database
Topologia e BFS traversal

Sorgente di verità del grafo infrastrutturale. Schema: (:Node) con proprietà rto_minutes, rpo_minutes, recovery_strategy. Relazioni -[:DEPENDS_ON]-> per BFS cascading failure. Il classificatore Eisenhower legge blast_radius e worst_case_rto_minutes da neo4j_client.py. Indici su Node(id) per lookup O(1). Porta 7474/7687.

FastAPI · Backend Python 3.12
REST API e logica di simulazione

Endpoint POST /api/dr/simulate esegue BFS + rto_rpo_calculator e restituisce EnhancedSimulationWithTimeline. Il classificatore Eisenhower viene invocato post-simulazione per determinare il quadrante e instradare verso il MCP tool corretto. Rate limiting e API key auth già implementati in api/dependencies.py. Porta 8001.

MCP Server · stdio · Porta 9001
Tool exposure per AI agents

Espone 4 tool: simulate_disaster (BFS + RTO/RPO), get_recovery_plan (playbook generation via Ollama + Qdrant), check_drift (Terraform vs Neo4j diff), get_simulation_timeline (query step-by-step). Integrazione diretta con Claude Code, GitHub Copilot e altri AI agents. Il clasificatore Eisenhower aggiungerà routing automatico Q1→Q3.

Playbook Generator · Ollama + Qdrant
Runbook per quadrante Q1 e Q3

Per Q1/Q3: seleziona _STATIC_STEPS_BY_STRATEGY (replica_fallback, multi_az, stateless, backup_fallback, generic) + chiamata Ollama LLM (nomic-embed-text, 768-dim) con context RAG da Qdrant. Step includono owner (DBA/SRE/on-call), estimated_minutes e comandi eseguibili.

VictoriaMetrics · Time-Series DB
Metriche live e trigger Q3

Scraping Prometheus: replication_lag_seconds, node_cpu_seconds_total, http_requests_total, application_errors_total. MetricsQL queries per rilevare Q3 (warning entro SLA) e trend deterioramento per promozione Q3→Q1. Retention 30 giorni. Basis per trend RTO/RPO sliding window 90 giorni (Q2). Porta 8428.

Governance lifecycle Q2

05 — Requisiti Non Funzionali
RNF-01 · Latenza di classificazione
Tempo di risposta Eisenhower Engine
Il classificatore assegna il quadrante e instrada verso il MCP tool corretto entro la finestra definita. Il BFS Neo4j per depth=5 è già benchmarkato a <500ms; il classificatore aggiunge <5ms di overhead computazionale.
≤ 30s (Q1) · ≤ 5min (Q2/Q3) · best-effort (Q4)
RNF-02 · Disponibilità
Uptime della DR Platform
Il backend FastAPI deve essere attivo anche durante un DR in corso. Docker Compose v2 con health check configurati su tutti i 6 container (neo4j, backend, frontend, victoriametrics, qdrant, ollama). Il classificatore non può fallire durante l'emergenza che gestisce.
99.95% uptime · Docker healthcheck su tutti i container
RNF-03 · Accuratezza
False positive / False negative rate
Il classificatore deve minimizzare i falsi Q1 (alert storm) e i mancati rilevamenti. Validato sulla test suite esistente test_enhanced_simulation.py con scenari storici reali e simulati. Soglie URGENCY_RATIO_WARN=0.70 configurabili.
False Q1 rate < 2% · Missed Q1 = 0% · coverage > 90%
RNF-04 · Tracciabilità
Audit log immutabile (structlog)
Ogni classificazione tracciata: quadrante, simulation_id, worst_case_rto, MCP tool invocato, timestamp. Già su structlog; estendere con WORM storage per DORA compliance. Validabile via /api/postmortem.
structlog JSON · 365 giorni retention · DORA-compliant
RNF-05 · Configurabilità
RTO/RPO thresholds per-nodo Neo4j
Ogni nodo Neo4j ha proprietà rto_minutes e rpo_minutes indipendenti, settabili via seed-rto-rpo.sh o bootstrap_neo4j.py. Il classificatore è agnostico dal tipo di nodo — legge solo properties generiche Neo4j.
Neo4j property update · No-downtime · seed-rto-rpo.sh ✓
RNF-06 · Sicurezza
API key + rate limiting già implementati
Il trigger playbook Q1 richiede API key (api/dependencies.py con verify_api_key già implementato) e rate limiting via limiter. Tool MCP stdio non espongono endpoint pubblici. Doppia autorizzazione per ambienti produzione.
API key auth ✓ · Rate limiter ✓ · MCP stdio isolation
RNF-07 · Estensibilità
Nuovi nodi via Terraform ingest
Aggiungere una nuova applicazione al perimetro DR richiede solo l'ingestione del Terraform state via parsers/infra.py. Il classificatore è completamente agnostico — legge rto_minutes e recovery_strategy come property Neo4j generiche.
Terraform → parsers/infra.py → Neo4j · Zero code changes
RNF-08 · Testing
Test suite esistente + nuovi unit test
Il progetto ha già test suite completa in backend/tests/. Il classificatore Eisenhower deve aggiungere test per tutti i casi limite: breach al 100%, breach al 70%, cascade_in_progress override, promozione Q3→Q1 su timer. Fixtures Neo4j mock già in tests/conftest.py.
